# 开发计划

## 广告数据存储

我们现在的广告数据有没有存储在数据库？是不是按天存储的？原子数据有哪些？

我们规划下：
能否用异步接口拉取所有广告近37个月前到3天前的每日[AdsInsights.Field.account_id,AdsInsights.Field.campaign_id,AdsInsights.Field.adset_id,AdsInsights.Field.ad_id,*ATOMIC_FIELDS]数据存储到数据库中，再转化为id+业务可用指标？然后调度器每天同步三天前未同步的数据。前端添加一个页面，展示已经同步的日期，并可以用实时接口创建任务手动重新同步某天数据。你觉得怎么样？

## 实施方案

### 数据存储

InsightsDailyDocument主键默认oid，支持 ad_id + date_start(改为date) 唯一索引，支持 account_id/campaign_id/adset_id + date 进行索引。
即便三年数据异步任务大概20分钟内可完成，问题不大。

### 指标转换

用现有的 get_atomic_metric 输出字典，再落库时直接持久化；

### 调度与补采

- APScheduler 每天 11:00 触发 `insights::daily_backfill`，抓取 `max(历史37个月,上次记录)` 至 3 天前的数据。
- 同步持续时间超过 1 年的补采任务会在执行前临时移除索引，加速落库，结束后重建索引。
- 失败的任务仅记录错误信息，由下次调度自动重试。
- 同步窗口按“广告账号 + 日期”计算，每个账号持久化 since 与 until，避免重复全量补采。

### 前端与接口

- 后端暴露 `/insights/sync/accounts`，返回按账号聚合的同步状态（含最近同步日期、覆盖区间和异常信息）。
- 移除手动补采接口，前端页面仅展示账号级别进度，支持手动刷新查看结果。
