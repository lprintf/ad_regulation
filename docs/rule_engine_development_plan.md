# 规则引擎开发计划

## 1. 背景与目标

- **业务目标**：实现一个支持广告自动化决策的规则引擎，覆盖规则定义、绑定、执行、监控与溯源，辅助广告关停与优化建议。
- **系统目标**：与现有 FastAPI 服务、ML 预测、广告控制等模块深度集成，保持统一的三层架构与依赖注入模式。

## 2. 核心能力范围

1. **规则管理**：规则元数据、版本、发布状态管理；规则使用 Python 脚本实现，可选参数化配置（YAML/JSON）。
2. **绑定机制**：支持 `规则名 + FBID` 主动绑定；解析新广告命名中 `[]` 的自动绑定；维护绑定历史与版本信息。
3. **执行调度**：基于 APScheduler 的周期任务，执行每日/每小时评估、延迟检查、自动解绑等流程，并记录计划时间与实际时间。
4. **输出结果**：生成结构化的动作、原因代码、优化建议，持久化到执行日志并可通过 API 查询。
5. **解绑策略**：检测连续 `n` 天未重启的广告并自动移除绑定，触发通知或状态同步。
6. **安全与审计**：规则执行沙箱、异常捕获、执行记录与审计接口对接。

## 3. 关键里程碑

| 阶段 | 目标 | 主要输出 |
| --- | --- | --- |
| MVP（第 1 周） | 基础规则 CRUD + 绑定管理 + 周期执行框架 | 数据模型、API、APScheduler 作业、执行日志表 |
| Phase 2（第 2-3 周） | 自动解绑、命名解析、执行结果结构化输出 | 自动解绑任务、执行结果 API、操作文档 |
| Phase 3（第 4-5 周） | 规则版本管理、灰度、监控与报警 | 版本控制、历史追踪、Prometheus 指标、告警配置 |
| Phase 4（第 6 周+） | ML 混合决策、规则可视化、管理后台 | 混合策略、前端界面、跨团队培训材料 |

## 4. 技术方案概述

- **架构集成**：在 `api/routers`、`api/services`、`api/models` 下新增规则域模块，保持 Router→Service→Data 分层。
- **数据存储**：在数据库中新增 `rule_definitions`、`rule_bindings`、`rule_execution_logs` 等表，复用现有 `utils/db.py` 会话管理。
- **规则执行**：使用 APScheduler 嵌入 FastAPI 应用，创建 interval/cron 作业；执行逻辑在 Service 层调用规则脚本。
- **脚本沙箱**：限制可用模块，使用受控 `exec` 环境或 `restrictedpython`，并在发布流程中执行规则单测。
- **日志与审计**：执行结果写入日志表，同步到 Activities API 或新建 `/rules/history` 接口；关键事件输出到现有监控。
- **通知通道**：预留 Webhook/Slack/email 通知接口，Phase 2 可先使用日志+管理 API。

## 5. 详细实施步骤

### 5.1 数据与模型

- 设计并迁移规则相关表结构（包含版本、状态、绑定、执行结果、心跳等字段）。
- 新增 Pydantic 模型和数据访问方法，覆盖 CRUD 与查询过滤。

### 5.2 API 与服务层

- 实现规则定义、绑定、执行、历史查询等 REST API，统一响应格式。
- 绑定逻辑：手动绑定（规则名+FBID）、批量绑定、新广告命名解析。
- 执行服务：加载规则脚本、注入上下文（广告数据、模型输出）、生成执行结果。

### 5.3 调度与任务

- 集成 APScheduler，配置作业启动/停止、失效监控、事件监听。
- 周期任务：规则执行（每日）、新广告扫描（每小时）、未重启广告检测（每日）。
- 执行过程中记录 `scheduled_run_time`、`actual_start_time`、执行耗时。

### 5.4 安全验证

- 发布流程要求：规则脚本提交附带单元测试、静态检查（如 `ast` 分析、黑名单关键词）。
- 运行时：隔离执行环境、捕获异常并记录，失败重试策略在 APScheduler 层配置。

### 5.5 输出与整合

- 执行结果结构化存储并通过 API 返回；与预测结果、Insights 数据交叉引用。
- 对接 Activities API，统一展示广告被关停的原因与规则来源。
- 预留与报警系统的接入点，支持 Phase 3 的告警需求。

## 6. 测试与质量保障

- **单元测试**：规则 CRUD、绑定逻辑、执行服务中的脚本上下文、输出生成。
- **集成测试**：APScheduler 作业触发路径、执行日志写入、API 端到端测试。
- **回归测试**：确保现有广告控制、预测接口不受影响，必要时添加契约测试。
- **监控**：为规则执行成功率、延迟、失败原因定义 Prometheus 指标和日志查询模板。

## 7. 风险与缓解

- **脚本执行安全**：通过沙箱、白名单、测试流程控制风险。
- **调度延迟**：监控 `scheduled_run_time` 与 `actual_start_time` 差值，超阈值告警。
- **数据一致性**：执行前后维护事务，失败时回滚绑定状态；对外 API 返回可重放的信息。
- **团队协作**：提前准备开发指南和代码模板，降低新规则 onboarding 成本。

## 8. 里程碑输出物

- 数据库迁移脚本、模型/Service/API 实现、APScheduler 配置。
- 规则脚本模板与沙箱工具、执行日志与历史查询界面。
- 运行手册（启停、调度配置）、监控仪表板说明、发布回滚策略文档。

## 9. 后续展望

- 将决策树/ML 模型结果解析为规则脚本，实现混合决策。
- 建立可视化规则管理后台，支持审批、版本对比和灰度发布。
- 引入实时通知（Webhook/Slack），并与 BI/报表系统联动。
